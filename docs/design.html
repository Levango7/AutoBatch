1. 概述

本原型演示一套可运行、可追溯、可扩展的大数据批处理工作流：从数据接入开始，经过质量校验、清洗、计算，到结果输出与可视化，全流程一键运行，并持久化每一份中间产物。

1.1 目标

  • 端到端可运行：示例数据（含注入缺陷）→ 五阶段处理 → 台账/质量报告/聚合结果，无人工干预。
  • 可追溯：每次运行独立批次号，原始/中间/最终数据全部持久化，带 sha256、行数、来源标记与血缘关系。
  • 可监控：每阶段独立日志与状态登记，失败能定位到具体阶段与原因。
  • 数据质量内置：完整性/唯一性/范围/格式/枚举/日期/引用完整性/异常值 8 类校验，不合格数据带原因码隔离并生成质量报告。
  • 规模可配置：处理量由配置文件控制，小样本快速验证，同样逻辑可扩展到更大规模。

1.2 范围与非目标

范围内范围外（后续演进）
单机批处理原型（Python 标准库，零依赖）生产级集群部署与运维（Spark 集群、资源调度、性能调优）

批处理（Batch）实时流式处理（Streaming）

2. 总体架构

架构分六层：数据源 → 接入 → 校验 → 清洗 → 计算 → 输出；横切能力为台账与血缘、质量规则引擎、日志与状态。原型阶段全部单机实现，各层接口保持与生产组件（见第 4 章映射表）一一对应。

3. 阶段划分与数据流转

流水线为线性五阶段，每阶段独立模块（src/stages/），通过共享上下文传递数据引用，产物全部落盘到批次目录 run/<batch_id>/。

阶段输入处理输出
1 ingestdata/raw/*.csv（外部数据源）字节复制 + sha256 + 行数 + 来源登记01_raw/、source 记录
2 validate01_raw/8 类规则逐行检查，隔离不合格行02_valid/、quarantine/、report/quality_report.*
3 clean02_valid/去重、填充、类型、金额、异常标记03_clean/orders_clean.csv
4 compute03_clean/四类聚合 + KPI04_aggregates/
5 output03_clean/ + 04_aggregates/最终数据集、看板数据、台账登记05_output/、manifest.json、status.json、metrics.json
运行实例（权威批次 B-20260815-134548-E85420）：接入 23,400 行 → 校验通过 22,268（隔离 1,132）→ 清洗后订单 19,068 → 91 天聚合 → 输出 19,068 行；各阶段耗时 158 / 1,524 / 673 / 858 / 1,117 ms（总 4,400 ms）。validate 已做外键集合预计算优化，2 万行约 1.5 秒（优化前约 21 秒，降幅 90%+）。

4. 技术选型

原型阶段采用零第三方依赖的 Python 标准库实现：保证一键复现、无安装门槛；五阶段接口抽象使引擎可替换。生产集群阶段的对应选型如下（依据 2026-08 调研，来源见第 10 章）：

6. 台账与血缘设计

6.1 manifest.json（批次台账）

{
  "batch_id": "B-YYYYMMDD-HHMMSS-XXXXXX",   // 批次号：运行目录名 + 台账主键 + 数据行标记
  "pipeline_version": "1.0.0",
  "config_digest": "sha256(配置)",            // 配置指纹，可复现运行条件
  "started_at" / "finished_at" / "status",   // 状态机：running → success | failed
  "source": {"name": "ecommerce-demo", "files": [{name, sha256, rows, path}]},
  "stages": [{name, status, rows_in, rows_out, duration_ms, log, error}],
  "artifacts": {相对路径: {path, kind, rows, sha256, batch_id}},
  "lineage": {产物: [上游产物]},              // 血缘边：表级（文件级），由各 stage 声明 + output 自动拼接
  "quality": {dq_score, checks_total, quarantined_rows, rules: [...]},
  "error": null
}

台账自校验能力：每个产物登记 sha256 与行数，可与磁盘文件随时比对（防篡改、防丢失）；血缘边描述 01_raw → 02_valid → 03_clean → 04_aggregates/05_output 的处理轨迹，中间产物语义对标 OpenLineage 的 TEMPORARY 数据集。

6.2 血缘自动推导

血缘采用声明式登记 + 集中拼接模式，不再硬编码字典：

  • 各 stage 在产出文件时，通过 ctx.lineage_decls[产物相对路径] = [上游相对路径...] 声明该产物的直接上游（如 04_aggregates/daily_sales.csv ← 03_clean/orders_clean.csv）。
  • ctx 为 PipelineContext dataclass（src/helpers.py），替换原 Dict[str, Any] 弱类型包，IDE 可静态检查阶段间传递的上下文字段。
  • output 阶段统一读取 ctx.lineage_decls，将其并入 manifest.lineage，无需在各 stage 重复维护硬编码边字典。
  • 权威批次共 17 个产物登记了血缘（含 kpi.json、dashboard_data.json 等聚合/输出产物），覆盖从 raw → valid → clean → aggregates → output 的完整轨迹。

6.3 状态与监控

  • 批次状态：running → success / failed（失败时 error 字段记录原因）。
  • 阶段状态：status.json 中逐阶段记录 status/rows/duration/log/error，失败可精确定位。
  • 每阶段独立 JSON Lines 日志（logs/<stage>.jsonl），异常含 trace 尾部。
  • run/latest.json 指针指向最新批次，支持多批次并存对照；时间口径：batch_id 取本地时间便于人工识别，台账 started_at/finished_at 为 UTC（相差 8 小时属正常）。

6.4 指标导出（metrics.json）

每批次在批次根目录产出 metrics.json（src/metrics.py），包含两类视图：

  • labelle 视图（stages 数组）：每个阶段一条记录，含 name/status/duration_ms/rows_in/rows_out，便于程序遍历。
  • flat 视图（metrics 对象）：扁平 key/value（如 stage_validate_duration_ms、pipeline_dq_score、pipeline_quarantined_total），便于直接作为 Prometheus gauge 暴露，以 batch_id 作为外部 label。

权威批次 metrics.json 摘要：total_duration_ms=4400、dq_score=0.996、quarantined_total=1132；各阶段耗时 158/1524/673/858/1117 ms。

8. 局限与演进

8.1 当前局限

  • 单机内存处理：百万行级以内；更大规模需换引擎（Spark/Dask）。
  • CSV 存储：无列式压缩与谓词下推；生产应换 Parquet。
  • 表级血缘：无字段级血缘自动解析（Python 变换无标准解析器，需声明式映射）。
  • 无调度/重试/告警：原型为一次性批处理，生产需接入 Airflow 类编排器。
  • 异常值仅标记不拒收（action=flag）：统计方法不宜硬性删行，业务规则应承担硬校验。

8.2 演进路线

  1. DAG 化：五阶段抽象为任务+依赖，迁移到 Airflow/Dagster（阶段纯函数化已就绪）。
  2. 引擎替换：stdin/stdout 数据接口保持，处理逻辑换 pandas → Polars → Dask/Spark。
  3. 存储升级：CSV → Parquet → MinIO + Iceberg/Delta（湖表格式补 ACID/时间旅行）。
  4. 质量平台化：规则库平移 Great Expectations/Soda，Spark 阶段引入 Deequ。
  5. 血缘标准化：manifest 字段对齐 OpenLineage 事件，接入 Marquez/DataHub；当前声明式 lineage_decls 可直接映射为 OpenLineage 的 dataset facets。
  6. 指标平台化：metrics.json 扁平 key 通过 Prometheus pushgateway 或 node_exporter textfile 采集，Grafana 构建流水线耗时/DQ Score/隔离数趋势看板与告警。
